1. 现役设计是什么、咬住它的是什么。

# 1 一页看懂

这条线要在「能造能用」的前提下，把几段铂管加各片法兰的总铂重降到最低。「能造能用」不是形容词，是一张有出处的判据表（第 3 节），按三关的次序判。

尺寸不是拍的，是一条因果链算出来的：

1. 20 °C/h 空管升温需要多大电流，这就是设计电流。<!-- 出处: Pt_Optimize/Core/LineRunner.cs:313 RampRateKPerH = 20.0 -->
2. 按设计电流密度 J（预设 10 A/mm²）定法兰每个必经截面。舌片厚 = 设计电流 ÷ (J × 舌片最窄宽)，不是旋钮。<!-- 出处: Pt_Optimize/Core/SectionSizing.cs:41；Pt_Optimize/Core/DesignSpec.cs:1029-1030 -->
3. 温度场和电流场决定槽和孔开在哪。
4. 剩下的旋钮由求解器调，落在图纸格上。交付的值就是被判过的值。<!-- 出处: Pt_Optimize/Core/Solver.cs:2642-2668 -->
5. 把网格一档档加密到数不再变。
6. 终验三关按次序跑：第一关升温全程，第二关带玻璃稳态，第三关空管到温，最后报铂重。全体截面的电流密度 I/A 都要小于设定 J + 1。<!-- 出处: Pt_Optimize/Core/FinalCheckReport.cs:26-29；HANDOVER.md:608；Pt_Optimize/Core/SectionSizing.cs:45 -->

形状（盘径、舌宽、锥形舌、挖不挖孔）由搜形状给出。

## 2.2 两条别改成「统一规格」的地方

- 四片板厚不能等厚。共用片承 √3 倍电流，等厚时发热按平方走是端片的 3 倍。等厚要么共用片烧，要么端片白花铂。<!-- 出处: Pt_Optimize/Core/LineSolver.cs:134-137 -->
- 舌保温各片各定。它不花铂，只是纤维。它是「管根低于热偶读数」这条的第一候选旋钮：包厚了，法兰与管根一起变热，管根不再被拉冷；但最热的铂也跟着变热，「最热铂高出热偶读数」变坏。所以每片的舌保温只能落在两条预算夹出的窗口里（4.7 节）。<!-- 出处: Pt_Optimize/Core/Solver.cs:288-289（冷侧候选舌保温打头；热侧不含舌保温，抬它只会更差）；Pt_Optimize/Core/Solver.cs:286（两条逐根反号） -->

舌保温按层包，每层 0.5 mm。合法值只有两种：裸舌 0.30 mm（0 层），或 0.5 mm 的整数倍。求解器交出的值一定落在这些值上。裸舌在热解里按 0.30 mm 内层保温、外表面发射率 0.45 计散热，不按裸铂 0.18；0.30 这个数仓库里查不到出处（第 8 节）。<!-- 出处: Pt_Optimize/Core/DesignScreen.cs:155-159；Pt_Optimize/Core/ShellThermal.cs:335-338 --><!-- 出处: Pt_Optimize/Core/Solver.cs:2636 InsLoMm = 0.3；Pt_Optimize/Core/Solver.cs:2668 QuantInsulMm = 0.5；Pt_Optimize/Core/Solver.cs:2653-2656 -->

圆盘保温整盘只有一个厚度，分不了内外环。<!-- 出处: HANDOVER.md:568 -->

## 3.2 两项温差预算：必须说清楚的一件事

「最热铂高出热偶读数」「管根低于热偶读数」两条的限值，出处是控温热偶的读数误差。热偶装在每段中点，误差 5 ℃；旧判法里「法兰增量温降 ≤ 10 K」那个 10，就是热偶上下两侧误差之和，现在拆成上下各 5。<!-- 出处: Pt_Optimize/Core/LineRunner.cs:319-328 -->

所以它的依据是测量，不是材料极限。不得据此声称「超过 5 K 也安全」，也不得声称「真实限值是 X」。

两项现在是参数表最上面一组「判据限值与可行窗口」里的设计输入，默认各 5 K。放宽多少由填的人负责；判据表、安装报告印的是本次实际用的数。<!-- 出处: Pt_Optimize/Core/DesignInputs.cs:90-100；Pt_Optimize/Core/ParamCat.cs:32；Pt_Optimize/Core/InstallReport.cs:179-181 -->

知道刻度来源后，有两条推论：

- 设计点别贴着限值摆。摆在测量地板上的判定分不出真假。
- 两条预算夹出一个窗口。同一片上，最热点与管根最冷端之差一旦大于两项预算之和（默认 10 K），把法兰整体抬温或降温都救不回来：抬温救了冷侧、害了热侧，降温反过来。要改的是这个温差本身（形状、挖料的位置），或者由设计输入放宽预算。<!-- 出处: 两条定义相加、基准消去，Pt_Optimize/Core/ThermocoupleBasis.cs:13-15；默认 5 + 5，Pt_Optimize/Core/DesignInputs.cs:94,100；理论模型 v7.0 第 6.3 节（docs/Pt_理论模型_v7.0.md 第 6.3 节） -->

## 3.3 看判据表的方法

裕度那一列比「过」有用。看到「过」先问两句：这个裕度比计算自己的误差大吗？比现场能分辨的尺度大吗？

计算自己的误差，程序会随结果一起交出来，叫认证误差：认证误差 = 放大 × 停机残差。<!-- 出处: Pt_Optimize/Core/LineRunner.cs:1011-1019 CertErrK --> 单位为 K 的硬判据，裕度的绝对值小于认证误差，判据表就印「无法判定」，说明里写「判不了那么细」。它不当过，也不当不过。<!-- 出处: Pt_Optimize/Core/LineRunner.cs:2588-2606 MarkUndeterminedIfInsideCertErr；Pt_Optimize/Core/Criteria.cs:235-241 --> 管孔净流入以瓦计，不进这条规则。<!-- 出处: Pt_Optimize/Core/LineRunner.cs:2582 --> 外层耦合的停机目标是绝对容差 0.025 K。<!-- 出处: Pt_Optimize/Core/LineRunner.cs:463 --> 两份记录在最终口径下的认证误差：【待补：W08/W06 最终重解】。

现场能分辨的尺度，就是上一节的热偶读数误差。

导航网格（2 mm）上算的数不能拿去决定；加密复算到数不再变之后的数才能。导航网格会把孔边和焊脚那一圈的梯度抹平，位移可以比裕度还大。判据表的数是不是加密复算之后的，看安装报告第 8 节标题（「判据已加密复算到数不再变」或「判据是导航网格上的数，还没加密复算」），或看状态面板的下一步是否还指「◆ 加密复算（算到数不再变）」。<!-- 出处: HANDOVER.md:1837（导航网格中带 2.0 mm）；Pt_Optimize/UI/LineDesignPage.cs:4218-4224,4341-4345,5529-5535；Pt_Optimize/UI/Flow.cs:689-695 --> 求根和判决用的是同一张网格：「把算例加密到 h」全仓只有一处实现，细粗比恒为 5.5。<!-- 出处: Pt_Optimize/Core/MeshAdapt.cs:456；HANDOVER.md:1831-1839 -->

判据只有三态：过、不过、无法判定。无法判定一律不算通过。<!-- 出处: Pt_Optimize/Core/Criteria.cs:235-241；Pt_Optimize/UI/ManualPage.cs:1352 -->

## 4.2 加厚板是双向的，别只算一边

加厚板同时做两件事：单位面积发热变小，法兰变冷；横向导热变强，从管子抽走的热变多，管根被拉冷。两件事的净效果是从管子多抽热：「管孔净流入」与「最热铂高出热偶读数」变好，「管根低于热偶读数」变坏。<!-- 出处: Pt_Optimize/Core/Solver.cs:268-286（方向依据：热侧板厚四片同号有用，冷侧板厚为负；该组数量在远离可行域的设计点上，只作方向） --> 所以「哪里热就加厚哪里」治得了热侧，却会把冷侧推坏。

按 J 定截面之后，板厚多半在下角就够了。冷侧的缺口由不花铂的舌保温和挖料补。

## 4.4 管保温 5 mm 别单独动

管保温对管根温度的杠杆很大，看着诱人。但它同时改设计电流。机理：管保温薄，管散热猛增，维持控温点要的电流变大；法兰发热按电流平方涨，而法兰的保温没有同比例变，法兰就反过来比管热。结果是热倒灌进管子（管孔净流入变负），最热的铂也比热偶读数高得更多。<!-- 出处: 机理 HANDOVER.md:8028-8031（旧判据下的实测记录，本版只取机理）；发热 ∝ I² 为焦耳定律 --> 这是推理，最终口径下没有扫过管保温。

所以改管保温就是改整条线的设计电流：判据表、舌片厚、板厚下角全部要重算。<!-- 出处: Pt_Optimize/Core/DesignSpec.cs:1030-1031（设计电流只与管、保温、工况有关） -->

## 4.7 每片舌保温的可行窗口

求解器交出的是最小的可行格点。现场关心的是另一件事：舌保温包偏一层，还过不过。终验时程序逐片回答它。<!-- 出处: Pt_Optimize/Core/InsulWindow.cs:18-24,225 -->

- 把一片的舌保温在解值 ±1.0 mm 内按 0.1 mm 挪，其余片、其余旋钮一位不动，每点跑一次整线。<!-- 出处: Pt_Optimize/Core/InsulWindow.cs:100-102,282-283 -->
- 过不过按整线的交付判定，与交付同一份。<!-- 出处: Pt_Optimize/Core/InsulWindow.cs:20-21 -->
- 报出解值所在那一段连续可行区间、宽度、区间里落得进的层数档（0 层即裸舌，也是一种做法），以及两侧边界外第一条不过的判据。<!-- 出处: Pt_Optimize/Core/InsulWindow.cs:21-24,168-180 -->

读结论：

- 任一片窗口里一个能包的档都没有，结论是「当前判据下无可制造设计」，并点名那几片。判据不改、不硬凑；要放宽，在两项温差预算里填。<!-- 出处: Pt_Optimize/Core/InsulWindow.cs:26-30,153-160 -->
- 窗口窄于一层（0.5 mm），点名那一片：现场包偏一层就出界。<!-- 出处: Pt_Optimize/Core/InsulWindow.cs:31,161-163 -->
- 扫到边界仍全过，记「边界没探到」，不把扫描宽度当成窗口宽。<!-- 出处: Pt_Optimize/Core/InsulWindow.cs:32 -->
- 解值那一点自己就不过，照实报，窗口无从谈起。<!-- 出处: Pt_Optimize/Core/InsulWindow.cs:33 -->

若有界，上侧一般由热侧卡住，下侧由冷侧或裸舌下界 0.30 mm 卡住：舌保温往上抬，热侧变坏；往下退，冷侧变坏。低于裸舌的点直接标「下界外」。扫描范围内没卡住时记「边界没探到」。窗口宽度，就是两项预算在舌保温这一根上留下的余地（3.2 节）。<!-- 出处: Pt_Optimize/Core/InsulWindow.cs:26-33,295-298；Pt_Optimize/Core/Solver.cs:2636 -->

这一步很慢：每点一次整线全耦合解，四片合计约一小时。所以只在终验跑一次，优化过程中不跑；开关在参数表，默认开。<!-- 出处: Pt_Optimize/Core/InsulWindow.cs:35-38；Pt_Optimize/Core/DesignInputs.cs:103-107 --> 目前只量舌保温这一根；板厚、环倍率、圆盘保温的窗口没有量。<!-- 出处: HANDOVER.md:843 -->

# 5 会骗人的坑

共同点：不报错、输出格式正常、数值看着合理，但结论是错的。

| 坑 | 怎么识破 |
|---|---|
| 贴着限值的「过」 | 看裕度列，不看「过」 |
| 裕度比认证误差还小 | 判据表印「无法判定」，说明写「判不了那么细」；它不是过，也不是不过 |
| 粗网格上的「过」 | 看安装报告第 8 节标题是否写「判据已加密复算到数不再变」；核算整线会自己走到那一步 |
| 未收敛的数 | 状态面板写「✗ 上次解未收敛」，并注明下面每个数都不可引用；② 页输出框也写「未收敛」 |
| 求解器说「判不了」 | 不是不可行，这一点没解到收敛；加轮数上限或细化网格重算，别去改形状 |
| 三关里写「没跑」的那一关 | 没跑不等于过；看是开关关了还是图纸模式 |
| 舌保温解值落在层上，但窗口窄于一层 | 看「舌保温可行窗口」页签与安装报告 8b 节 |
| 看不见却在起作用的量（角焊缝）；有框但容易忽略的（压接段、渐变环、逐片舌保温、舌根圆角） | 输出框每次算完都逐条印实际用值，看一眼 |
| 换了牌号，热学结论却一位没动 | 该牌号的电、热数据不全，电阻率、电阻温度系数、热导率、比热一起退回纯铂；结果说明末尾写了缺哪几类。数据齐全的牌号（Pt-Rh/90-10、Tanaka-ZGS-Pt、Tanaka-ZGS-PtRh10）会变 |
| 参考量越了限 | 参考量只印值与裕度，不卡交付；旧判法两条也在参考量里 |
| 两个按钮给的数不一样 | 一个算的是存好的设计记录，一个算的是改过的页面；页面上的数和记录一样时两边给的就是同一个数 |

## 7.3 核算整线 vs 搜形状

| | 核算整线 | ◇ 搜形状（手动分步） |
|---|---|---|
| 回答的问题 | 这个设计能不能用、能不能造 | 能用的前提下哪个盘径／舌宽／舌形最省铂 |
| 什么时候点 | 每次改完输入或读完图纸都先点它 | 核算整线在解析模式下旋钮到顶时会自己接着搜形状，不用人点；想单独在形状这一维上看结果、当前形状全过但想更轻、想拿一张形状表自己挑时才手动点。判「判不了」时不要点它 |
| 它会动什么 | 先只调旋钮；法兰侧旋钮到顶时，它按下一步指路接着搜形状（会改盘径与舌宽） | 盘径、舌宽、平行或锥形；两个都算时不挖孔、挖孔各搜一遍、各选各的最轻 |

## 7.4 用自己的 Rhino 图纸

① 输入页「法兰几何来源」选「Rhino .3dm 文件」，在「法兰图纸 .3dm」一行点「…」选一张图（各片同一张图、厚度各自解），填图层名，段数在「铂金管加热段数」框里定。<!-- 出处: Pt_Optimize/UI/ManualPage.cs:1147-1159；Pt_Optimize/UI/LineDesignPage.cs:4648-4650 --> 不先分析，两条几何判据是「无法判定」，不算通过。点「核算整线」时，它会自己先分析图纸、照图纸解一次作基准，再交给解析路。<!-- 出处: Pt_Optimize/UI/Flow.cs:401-418,522-541；Pt_Optimize/UI/LineDesignPage.cs:2367-2373 --> 手动分步时先点「分析几何变数」；要搜形状，先点「◈ 图纸几何 → 参数」把图纸变成参数。

图纸模式下结果说明里可能多出两句「⚠ 片n：…」，都只量不判、判据照常出数：一句是「图纸路径管孔弧缺 x mm @ θ°，覆盖率 y」——程序按栅格读图，栅格原点不巧时孔圆上某一段没有落到任何格的孔边界面上，那一段等于绝缘，电流要绕到缺口两端进孔，孔边电流密度峰（参考量「· 法兰 J_max」）会偏高（实测一例 W08 盘 R31 判决档缺 2.0 mm 时偏高约 49 %）；θ 从 +x 轴量，180° 是舌片一侧。换栅格步或原点缺口会变。另一句是「图纸孔半径 … 与 rh = 管内径/2 + 壁厚 … 差 … mm，超过一个栅格步」——网格按 rh 建孔边，图纸上的孔与它错位时，孔边的电流与热流按错位的孔算。这两句出现时，吃孔边场的判据要不要算「判不了」，尺怎么定，还没有定。<!-- 出处: HANDOVER.md §0.-20；Pt_Optimize/Core/ShellMesh.cs MeasureHoleArcCoverage；Pt_Optimize/Core/LineRunner.cs HoleArcDrawingNotes；Pt_Optimize.Tests/R48ArcGapDiagTests.cs -->

## 7.5 常见问题

| 现象 | 其实是 |
|---|---|
| 「◇ 搜形状（手动分步）」是灰的 | 图纸模式，先点「◈ 图纸几何 → 参数」；或当前参数还没点过「核算整线」并收敛 |
| 选了「（已作废）」的档，导出 3DM 没反应 | 故意拦住的，已作废的档不许出图 |
| 图纸模式的结果说明里有「⚠ 片n：图纸路径管孔弧缺 … mm @ …°」或「图纸孔半径 … 与 rh … 差 … 超过一个栅格步」 | 只量不判：栅格原点让孔圆某段没有孔边界面（等于绝缘，孔边 J 峰偏高），或图纸上的孔与程序按管内径/2 + 壁厚建的孔错位；判据照常出数，要不要算判不了还没定（7.4 节） |
| 核算整线停在「不可行（法兰侧旋钮到顶／分派前提不成立／没有旋钮能治 …）」 | 核算整线会自己接着搜形状。停在这里，说明形状也搜过了，要改输入（控温点、管径与管壁、铂牌号，或放宽这一段的工况） |
| 核算整线停在「判不了」 | 这一点没解到收敛，不是不可行；重解时加轮数上限，或点「◆ 加密复算（算到数不再变）」在细网格上重算；不要去改形状 |
| 判据表某条印「无法判定」，说明写「判不了那么细」 | 裕度小于认证误差；要判得了，得在细网格或更细容差上重算 |
| 加密复算后从过变不过 | 导航网格把孔边和焊脚那一圈的梯度抹平了；点「◆ 细网格重解（加密不过后）」 |
| 三关结论里第一关或第三关写「没跑」 | 左侧参数表最上面「0 判据限值与可行窗口」那组开关关了，或者是图纸模式 |
| 牌号下拉里有灰的行 | 四类数据不全，行末写着缺哪几类 |
| 安装报告第一行写「不可作为安装依据」 | 判据没全过，或外层耦合未收敛；回 ② 页解到全过 |
| 搜形状结果比设计记录重 | 它保证「过」，不保证比记录省；到 ① 页换一个盘径／舌宽再搜，或在「搜形状结果 ▾」里挑 |

| 量 | 现在按什么算 | 一旦不同，影响多大 |
|---|---|---|
