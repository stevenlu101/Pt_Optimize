### ② 白名单：**不要名单，要一条机械判据**

你怕「又是一个看起来有门的白名单」—— 这个怕是对的。名单会腐烂，判据不会。

判据只有一条，看**断言的对象是什么**：

```
Assert.Contains(str, <运行时产生的值>)     ✅ 正当 —— 这是行为门
    例：Assert.Contains("增宽", res.TerminalWhy)
        Assert.Contains(res.Trace, s => s.StartsWith(BranchMarks.MeltHandOff))
    它验的是「程序跑出来说了什么」，措辞变了就是行为变了，本来就该红。

Assert.Contains(str, <读进来的源码文本>)   ⚠ 嫌疑 —— 这是拿实现文字当行为的代理
    例：Assert.Contains("先加厚这一级", s)        ← s = File.ReadAllText(Solver.cs)
    它验的是「某个方法里有这行字」，改个写法就红，而行为一点没变。
```

嫌疑那一类里，**唯一正当的例外**是：**那个字符串本身就是要求**，而不是某个行为的代理。

```
BannedVocabularyTests   「被禁的词」—— 词本身就是要求          ✅
DocRefTests             「不许出现 xxx.cs:行号」—— 写法本身是要求 ✅
NoCriterionCodeInUiTests「②′ 不许出现在界面」—— 代号本身是要求   ✅（若它是扫源码的话）
```

⇒ 机械判据（可写进门里，不需要人维护名单）：

```
读源码的断言中，被钉的字符串**如果同时出现在产品代码的字符串字面量里**
（= 对外文案／被禁的词），算正当；
如果它出现在产品代码的**语句或标识符**里（= 实现细节），算嫌疑。
```

这条能自己算，不靠人记。你先拿它跑一遍那 62 档，**量出「嫌疑」有多少条**——
那个数才是欠账，403 不是。
