## 0　结论（给编排者）

1. **抽取器源码在仓库里**：`Pt_Optimize.Geom/Program.cs`（1760 行，受跟踪），项目 `Pt_Optimize.Geom.csproj`（net7.0-windows、x64、`Rhino.Inside 8.0.7-beta`，编译期带出 RhinoCommon 8.0.23304.9001）。不是只有可执行件。主程序只通过子进程调它（`Geometry3dm.FindProbe` 找 `Pt_Optimize.Geom/bin/{Release|Debug}/net7.0-windows/Pt_Optimize.Geom.exe`）。
2. **抽取器现在不认孔**：`thickness` 模式只读**实体**（Brep／Extrusion），不读曲线。它在 x–z 栅格上逐点沿 Y 打射线、把交点配对累加成厚度 t(x,z)，t = 0 就是无料。孔是在**主程序**里认出来的：`PlateShapeAnalyzer.FindVoids` 从图幅边界做连通填充，剩下被材料包围的 t = 0 连通域里**最大的那个就是管孔**，半径取等面积圆（`HoleRadiusOf`／`Analyze` 同一式）。图层名只用来挑实体，不用来认孔；也没有闭合曲线的包含关系。
3. **API 可行**：本机 nuget 缓存里的 RhinoCommon 8.0.23304.9001 XML 文档查到这些条目：`Intersection.BrepPlane`、`Curve.JoinCurves`、`Curve.TryGetCircle(out Circle, double)`、`Curve.TryGetArc`、`Circle.TryFitCircleToPoints`、`Surface.TryGetCylinder`、`AreaMassProperties.Compute(Curve[, double])`、`AreaMassProperties.AreaError`、`Curve.GetDistancesBetweenCurves`、`Curve.Contains`、`BrepLoopType.Inner`、`BrepLoop.To3dCurve`。抽取器已经在用 `TryGetCylinder`（默认模式第 396 行，`--geom` 报告拿「最小圆柱半径」当管孔，Geometry3dm.cs:779）。另查到 `AreaMassProperties.CentroidError`（since 5.0）。各条目 since 标签：BrepPlane、JoinCurves、TryGetCircle、AreaMassProperties.Compute(Curve)、AreaError、CentroidError、GetDistancesBetweenCurves、Curve.Contains 为 5.0，TryFitCircleToPoints 为 6.2（`R48_决98_乙核实_读码证据_本次开跑于2026-09-23_161526.txt` 第 J 节）。**Windows 那台机器上装的是哪个 Rhino 8 小版本，未查到。**
   - **.3dm 在 Linux 上能读**：rhino3dm 8.35.0（装在 scratchpad，未动系统 python）已读出五张图的单位、容差、圆边、圆柱面（`R48_决98_乙核实_rhino3dm读孔圆_本次开跑于2026-09-23_161305.txt`，修订复跑 `R48_决98_乙修订_rhino3dm复跑_本次开跑于2026-09-23_161939.txt`）；README.md:70 记载 `Pt_Heater.3dm` 最初就是用 rhino3dm 提取的。rhino3dm 不带 `Intersection.BrepPlane`，本工单的截面法仍要 Windows + RhinoCommon；Linux 读法只作核对用。
4. **最小改动**（尺、门、优先级、R_mesh 取法都待决 98 业主拍板）：抽取器在 `thickness` 模式里，对**同一组实体**（与栅格同一个 `parts`）多带出一个 `holeCircle`（半径、圆心、拟合残差、容差、来源 = 曲线）。主程序给 `ThicknessField` 加一个可空成员 `HoleCircle`（缺省为空）。图纸路径的规则：
   - 有 `HoleCircle` 且可用：失配 = R_曲线 − rh，尺 = 抽取器精度。
   - 超过尺：带内判料、F6 孔面、热锚点**都按 R_曲线**。
   - 在尺内：仍用 rh，保证与改前逐位相同。
   - 没有 `HoleCircle` 或不可用：退回甲；甲没落地时退回现行 rh。
5. **Windows 专属步骤**：只有抽取器那一段、真图纸的门、界面抓图要 Windows。Core 的接口、退路、说明句、快门都能在 Linux 镜像上先做（镜像不含 Geom，用合成的 `HoleCircle` 喂内存场）。

## 3　从 Rhino 几何精确读孔圆：做法与可行性

### 3.1　读哪一种几何

- 抽取器看到的是实体，不是草图曲线。「孔圆」要从实体上取：管孔的孔壁是一个圆柱面，它和中面的交线是一个圆。
- 推荐主法 = **截面环**（**切在哪里已按下面的修订改为逐段切**；原稿：对本组每个实体，在**它自己的** Y 中点用 `Intersection.BrepPlane` 切一刀，拿到截面线；用 `Curve.JoinCurves(…, tol)` 连成闭合环，投到 x–z）。
  - ~~为什么按实体各自的中点切、不用全组的 PlaneY：台阶级可能只在一侧加厚，那种级的实体不一定跨过全组中面。孔壁沿 Y 是柱面，在实体内任何一个 y 上切出来都是同一个环。~~ **此前提对阶梯孔不成立，已改**（核实 2026-09-23）：
  - `Pt_Heater3.3dm` 法兰层是**单个阶梯 Brep**，实体顶点 y 只有 −1／0／1／2（`R48_决98_乙修订_rhino3dm复跑_本次开跑于2026-09-23_161939.txt`；rhino3dm 的对象包围盒读成 −1.1 是松包围盒，抽取器 :438 用精确包围盒）。孔壁半径随 y 变：R26 柱面在 y −1～0（面 4），R36 在 0～1（面 9），R46 在 1～2（面 7）；另有 r 31～36 的四个槽，贯通 y −1～0 那一级（`R48_决98_乙核实_rhino3dm读孔圆_本次开跑于2026-09-23_161305.txt` faces 列表；`R48_决98_乙修订_rhino3dm复跑_本次开跑于2026-09-23_161939.txt` 边表）。
  - 按原规则在实体 Y 中点 0.5 切一刀（**推断，未实跑**：rhino3dm 不带 BrepPlane），切到的内环是 R36；环内侧 r∈[26,36] 在 y −1～0 有料（槽所在角度除外），射线判为有料 ⇒ 不是空腔环 ⇒ 该图乙给 null，退回甲。
  - **改为**：要读贯通孔（与 `FindVoids` 的沿 Y 投影定义一致），在本组相邻两个平面面 y 值之间**各切一刀**（Pt_Heater3 即 y −0.5／0.5／1.5），逐刀按 §3.2 取空腔环，再在全部刀的空腔环里取面积最大者。Pt_Heater3 上 y −0.5 那一刀切到的 R26 环内侧整条射线无料、外侧有料 ⇒ 是空腔环（推断，未实跑）。
  - 备选：对轴平行 Y 的圆柱面按 y 取最小半径包络（等价于投影后的最小内孔），与截面法互证。
  - 慢门要带阶梯孔例（见 §6 慢 d）。
- 备查法 = **孔壁面**：`BrepFace.UnderlyingSurface().TryGetCylinder(out cyl, tol)`，只留轴平行 Y 的圆柱面。用它和主法互相印证。圆柱面常被拆成两半，要按圆心和半径在 tol 内合并。

### 3.2　哪个环是管孔（与栅格同一个定义）

1. 找空腔环：沿环取点 p，向环内、环外各挪 δ（δ = 5·tol，沿用抽取器已有的离擦边带距离，:541），用**同一个射线测厚**判料。环内无料、环外有料 ⇒ 这个环围着一个空腔。
   - 取点数属于**选定**（例如 8 个），只用来分类，不进任何量值；全部点都满足才算空腔环。
   - 这一步会排掉台阶级之间的分界圆（两侧都有料），也排掉外轮廓（环内有料）。
2. 在空腔环里取**面积最大**的一个当管孔，与 `FindVoids`「最大的那个是管孔」同一个定义。其余空腔环（舌孔、槽）只数个数，写进 `voidLoops`。

### 3.3　半径、圆心、残差

- 半径：`R = √(A/π)`，A 取 `AreaMassProperties.Compute(环, tol).Area`。这就是 `HoleRadiusOf` 的等面积圆定义的**精确版**，甲、乙两个数可以直接对比。
- 圆心：同一次计算给出的面积形心 (cx, cz)。
- 残差：ρ = `Curve.GetDistancesBetweenCurves(环, 圆(cx,cz,R), tol, out maxDistance, …)` 的 maxDistance，即环与圆之间的最大距离，不靠取点数。
- 来源标记：
  - `TryGetCircle(out c, tol)` 成功 ⇒「曲线·圆」，另记 c.Radius；它与 R 的差应 ≤ tol，写进 JSON 以便核对。
  - 不成功 ⇒「曲线·非圆」，照报 R、ρ。
- **尺（抽取器精度），各项都在运行时量出，不发明常数**：尺_乙 = tol + ρ + AreaError ÷ (2πR)。
  - tol = `doc.ModelAbsoluteTolerance`，截面交线离真实截面在 tol 以内（`BrepPlane` 的容差参数）。
  - ρ = 环离所报圆的最大距离。
  - AreaError ÷ (2πR) = 面积误差折成的半径误差（dA = 2πR·dR）。
  - 圆心误差：`AreaMassProperties.CentroidError`（since 5.0）同一次计算给出，进孔心判据（下条）。
  - 圆孔上 ρ ≈ 0，尺约为一个文档容差。五张图（Pt_Heater1／Pt_Heater3／Pt_Heater／设计记录_管壁0.8mm／0.6mm）的单位都是 mm、`ModelAbsoluteTolerance` 都是 **0.001**（`R48_决98_乙核实_rhino3dm读孔圆_本次开跑于2026-09-23_161305.txt`，`R48_决98_乙修订_rhino3dm复跑_本次开跑于2026-09-23_161939.txt` 复跑同值）。`RunThickness` 在 :425 已拿到 tol，`holeCircle` 直接带出 `TolMm` 即可，不必另跑默认模式。`RunThickness` 不做单位换算（Program.cs:419–574 里没有 `UnitScale`／toMm；默认模式 :317–318 才读单位），所以 JSON 里应写明 `units`，或在主程序侧校验为 mm 再用 R 与 TolMm。
- 可用性门（不引新数；**待决 98 业主拍板**）：尺_乙 < 当前栅格步 s 才算「可用」，否则曲线读数不比栅格好，退回甲。另加一致性检查：|R_曲线 − HoleRadiusOf(栅格)| ≤ s/√2 + 尺_乙，这是两个误差界相加。s/√2 是推导出的误差界（PlateShapeAnalyzer.cs:118–126），不算业主那把尺；但它与 HANDOVER §0.-20 待决定 3（HANDOVER.md:91「失配的尺用一个栅格步，还是用更紧的 s/√2」）是**同一个数**，拍板时要一并看。不满足就写一句「曲线孔径与栅格孔径不一致」，并退回甲；常见原因是锥孔、倒角孔，或者孔跟槽连在一起。
- 孔心判据：|c| ≤ 尺_乙 + CentroidError（原稿只用尺_乙，漏了形心误差）。

### 3.4　各种情形

## 10　风险

1. **孔不是圆**：锥孔、倒角孔、非圆舌孔被当成管孔、孔和槽连通。靠 ρ／可用性门／与栅格的一致性检查兜住并退回甲，照样写说明句。网格按圆建孔的前提在这些图上本来就不成立，本工单不解决。
2. **一图层多片与阶梯孔**：曲线圆必须来自与栅格**同一组**实体（共用 `parts`）；planeY 没给时沿用现有 Warning。现存多片图是 `Pt_Heater.3dm` 法兰（4 片）；`Pt_Heater3.3dm` 是单片阶梯孔（R26／R36／R46），按「实体 Y 中点一刀」读不到贯通孔，必须按 §3.1 修订的逐段切法。
3. **孔心偏移**：网格、孔弧面、分级轴都假设管轴在原点。偏离超过尺时只报、不启用曲线圆。要不要把网格平移到孔心，是另一个决定，本工单不做。
4. **与决 98 甲的接口**：
   - 两者输出同一个量（带内判料用的孔半径）。优先级是乙 > 甲 > rh。
   - 尺各自独立：乙 = 抽取器精度（tol + ρ + 面积误差项）；甲 = 相位扫描实测。
   - **孔带宽度不随尺变**：带宽由栅格台阶决定（RING：HoleBandPerStep × s），与量孔的精度是两件事。
   - 乙可用时，小于一格的真失配（例如导航档 +0.3 mm）**会报**，也**不会**被孔带吸收；乙不可用时仍是甲的行为。
5. **判据几何与网格不同圆**：GeomForJudge、焊脚、`MeshInnerRadiusMm` 仍按 rh，网格按 R_曲线。失配超过尺时两者差一个失配量。同一个诊断量里也会混两个圆：`HoleTagBeyondWeldMm` = `mesh.HoleTagLengthBeyondMm(c.WallMm)`（LineRunner.cs:2233、2241），孔标签按 R_mesh、焊脚按 rh 口径。这是决 98 口径的一部分，本工单只量不判。
6. **尺太小带来的「真报」**：曲线读数精到 ~tol，只要图纸孔径与所选壁厚对不上（例：Pt_Heater1 按栅格读是 R26.00，而现役壁厚 0.8 ⇒ rh = 25.8），就会报出真实失配，说明框里会多出句子。这是本意，但会改动 .3dm 路径上的说明文字与数。
7. **WithThickness 漏带 HoleCircle**：按本工单接线，缩放后的场上没有读者会读 HoleCircle（§4），不会静默退回；照抄仍要做，门守的是接口约定。
8. **Windows 上的 RhinoCommon 版本**：API 都是 5.0／6.2 起就有，风险低。实际装的版本未查到。
