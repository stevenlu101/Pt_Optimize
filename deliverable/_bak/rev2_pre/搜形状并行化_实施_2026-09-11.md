## 1. 改了什么

| 文件 | 改动 | 为什么 |
|---|---|---|
| `Pt_Optimize/Core/ShapeBatchEval.cs`（新） | `RunAsync<TCandidate,TResult>(candidates, solveOne, lanes, ct)`：`SemaphoreSlim(lanes)` 限流，每个候选 `Task.Run`，结果按输入下标装回；`lanes=1` 与 `lanes=4` 走同一段代码；取消返回 `Outcome{Results, Done, Cancelled}` | 审查第 4 节：同进程限并发，不做多进程（Solve 链路没有会被搜形状碰到的非线程安全共享状态；`SolverResult` 含委托字段，跨进程要另造 DTO）。取消不抛而是带回「哪些完成了」——否则 `await` 一抛，已经算完的候选跟着丢（用户要求「已经算完的形状结果不会丢」） |
| `Pt_Optimize/UI/LineDesignPage.cs` `SearchShapeAsync` | 新增局部函数 `EvalShapesBatch(pts)`：UI 线程先做早筛（判据「圆盘盖得住管孔＋焊脚」）与 `PageToDesignSpec()` 组候选；`Solver.Solve` 4 路并发；批完按候选原顺序贴回 `rows`／输出框／进度。⑥「剩余舌宽比例」与 ⑦「邻域探索」两处循环改调它；`_prog.Maximum` 整批一次加 | 审查第 0 节：只有 ⑥⑦ 本轮内候选互相独立；③④⑤（不动点／二分／黄金分割）逐次依赖，一行未动。审查第 3 节：`PageToDesignSpec` 等同步前缀不能离开 UI 线程；`done/baseDone` 快照计数会倒退 ⇒ 改成整批计数 |
| 合入时修 | lambda 里直接读 `FamilyAllowsCuts`（跨线程读 ComboBox）⇒ 批前在 UI 线程取成局部值 `allowCutsBatch` | WinForms 控件属性只能在 UI 线程读；Release 下不抛只是运气 |
| 合入时修 | 慢测里子代理加的「实时轨迹」Progress 回调（四路并发往同一文件 `File.AppendAllText`，回调落在线程池）去掉 | 子代理那次慢测「测试主机进程崩溃」，根因没抓到（应用程序日志无 .NET Runtime 记录）；先去掉唯一的多线程共享写入再重跑 |
